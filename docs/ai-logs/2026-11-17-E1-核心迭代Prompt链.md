## 链 1：新增 AI 批改 Agent（分步诊断 + 更优解法 + 流式）

### 1.1 我的提问（任务书原文）

```
新增第七个 Agent：批改（review）。要求：
1. 输入题干、标准答案、学生作答；输出 JSON：score / steps / first_error / better_method / method_comparison
2. steps 要分步给分，能指出「错在第几步」，不是只给总分
3. better_method 给更优解法，并和学生的方法对比
4. 评语要流式显示，不能等整段生成完
5. 不改 explain 的既有接口，前端新增 ReviewPanel
```

### 1.2 AI 的建议

- 复用 explain 的流式管线（`chat_stream` + SSE `delta`）；
- 先把结构化结果（分数、步骤、首个错误）一次性生成，再用同一路 SSE 流式推评语；
- 事件类型沿用 `review/delta`、`review/done`，`done` 里带全部结构化字段。

### 1.3 我的判断

| 建议 | 采纳？ | 理由 |
|---|---|---|
| 复用 `chat_stream` | 采纳 | 已有真流式 + mock 模拟流的分层，不重复造 |
| review 复用 explain 的题目上下文 | **否决** | 两个 Agent 的数据来源应独立（explain 读题目，review 读作答记录 `attempt`），复用会让「讲解」和「批改」互相绑死 |
| 先结构化再流式 | 采纳 | 前端可以先把分数与步骤渲染出来，评语边到边显示 |

### 1.4 我如何引导修 Bug

现象：评语按 8 个字一片推送，一屏刷几十条，读起来是「抖动」而不是流式。

1. 我先看事件时间戳，确认不是网络问题，是切片太小；
2. 要求改成「缓冲满 20 字再发 12 字」，末片允许 8–19 字；
3. 同时要求把文档里「攒够 8 字就发」改成实际口径，避免文档与实现相反（这条后来被独立评审抓过一次）。

### 1.5 落地

- `agents/review.py`：`REVIEW_BUFFER_CHARS = 20`、`REVIEW_CHUNK_CHARS = 12`；
- `POST /api/review`，事件 `review/steps` → `review/delta` × N → `review/done`；
- 前端 `ReviewPanel`：分数环 + 步骤清单（错误步骤红标）+ 方法对比 + 流式评语；
- 测试：`test_review.py` 覆盖 partial/满分/空作答、流式片数与末片长度。

## 链 2：P0 —— `sympify` 把模型输出当代码执行

### 2.1 我的提问（含实测证据）

```
独立评审实测：
sp.sympify("__import__('os').getcwd()")        → 真的执行
sp.sympify("open('pwn.txt','w').write('x')")   → 真的创建文件
位置：app/agents/verify.py 的 check_question，subs 的值同样来自模型。
触发条件：切真实模型后命题返回的 verify.expr 由模型生成。

要求：
1. 解析前做字符白名单，只允许数字/变量/运算符/括号/逗号
2. 改用受限 parse_expr（__builtins__ 置空），不要裸 sympify
3. subs 的 key 只接受单字母，value 只接受数值
4. 补测试：恶意表达式必须返回 False 且不产生文件
5. 不改 apps/web、docs、scripts，不执行 git 命令
```

### 2.2 AI 的建议

三层防护 + 独立模块：

| 层 | 做法 |
|---|---|
| 字符白名单 | `^[0-9A-Za-z.+\-*/^(),= ]+$`；`_`、引号、方括号、反斜杠直接拒绝 |
| 标识符白名单 | 长度 1 视为变量；长度 > 1 只允许 `sqrt sin cos tan abs exp log ln` |
| 受限解析 | `parse_expr(code, global_dict={"__builtins__": {}}, local_dict=…)` |
| subs 限制 | key 单字母；value 仅 `int/float` 或可 `float()` 的数字串 |

### 2.3 我的判断

- 采纳三层方案，但**否决**「用正则过滤关键字（import/open/eval）」作为主防线：黑名单永远漏，必须是白名单；
- 要求把解析收敛到**唯一入口** `app/safe_math.py`，`verify.py` 与 `fixtures.py` 都改走它，避免以后再有人直接调 `sympify`；
- 要求补「运行后目录里没有新文件」的断言，而不是只断言返回 False。

### 2.4 我如何复验（不采信汇报）

自己写脚本打 6 个载荷 + 1 个 subs 注入 + 1 个正常表达式：

```
临时目录：C:\...\Temp\yz-p0-aatvb_r1
运行前文件：[]
PASS  __import__('os').getcwd()          -> 表达式含非法字符
PASS  open('pwn.txt','w').write('x')     -> 表达式含非法字符
PASS  eval('1+1')                        -> 表达式含非法字符
PASS  exec('import os')                  -> 表达式含非法字符
PASS  ().__class__.__bases__             -> 表达式含非法字符
PASS  os.system('echo hi')               -> 表达式含非法字符
PASS  subs 注入                           -> subs 的值不是数值
PASS  正常表达式                          -> x**2 - 4*x + 3 @ {'x': 2} = -1，期望 -1
运行后文件：[]
```

### 2.5 落地

- 新增 `apps/server/app/safe_math.py`；全仓 `app/` 下已无裸 `sympify` / `nsimplify`；
- 新增 46 项测试（`test_safe_math.py` 36 + `test_mock_questions.py` 10），总数 192 → 238（后续继续加到 395）；
- 技术文档里「沙箱性来自语言子集本身」的错误表述同步改为「只接受受限算术表达式」；
- 教训写进评审处置表：**文档声称的安全性必须用攻击载荷实测一次**。

## 链 3：mock 出题跟着卡片走 + 单文件版读 `.env`

### 3.1 我的提问（问题 1）

```
上传三角函数的样例图，卡片已经是三角函数，但生成出来的 5 道题全是二次函数。
事件里还写着「按需求命题：出 5 道三角函数的题」，自相矛盾。
要求：
1. mock_questions 按 cards 的 tags/subject 判定样例集（quadratic/equation/trig）
2. 认不出时回落二次函数
3. 第 1 轮固定有 1 题验算失败（演示回环要用），第 2 轮全过
```

### 3.2 AI 的建议

- `mock_questions(round_no, cards)`：先解析 tags（兼容数组与 SQLite 逗号串），按 trig → equation → quadratic 顺序判定；
- 三套题各自带 `verify`，第 4 题在第 1 轮故意 `expect=1.0`（正确 `-1`）；
- `llm._mock("compose")` 把 `payload["cards"]` 传进去。

### 3.3 我的判断与修 Bug

- 采纳主题分流，但要求**验算序列可断言**：第 1 轮必须是 `[T,T,T,F,T]`，第 2 轮全 T——否则演示时「有时驳回有时不驳回」；
- 发现 `expect` 非数值时会抛异常把整批打成 `orchestrator/error`，要求把 `float()` 移进 try，返回「期望值不是数值」而不是中断。

### 3.4 我的提问（问题 2：单文件版读配置）

```
单文件版（portable）每次解压到 %TEMP%，把 .env 放在 exe 旁边读不到。
能不能支持？要求：
1. 目录版行为不变（exe 同级 .env）
2. 单文件版也能读 exe 同级 .env
3. 没有该文件时行为与现在逐字节一致
```

### 3.5 AI 的方案与我的验证

- Electron 的 portable 目标会传 `PORTABLE_EXECUTABLE_DIR`，主进程据此拼 `<exe 目录>/.env`，通过新环境变量 `YIZHI_ENV_FILE` 传给后端；
- 后端先加载 `YIZHI_ENV_FILE`，再用程序目录 `.env` 补齐（缺省无该变量时完全不变）。

我的实测（v0.1.6）：

```
portable + .env 就位: .env, YizhiChengke-0.1.6-portable.exe
health: {"ok":true,"vlm_provider":"qwen","llm_provider":"qwen",...,"ready":true}
残留: 0
```

### 3.6 落地

- `fixtures.mock_questions(round_no, cards)` 三套题；`test_mock_questions.py` 10 项；
- `config.py` 增加 `YIZHI_ENV_FILE` 覆盖；`main.js` 在 portable 下设置该变量；
- 版本 0.1.6，395 项测试全绿。

## 这三条链共同的方法

| 做法 | 说明 |
|---|---|
| 先给证据再下结论 | 报 Bug 时附命令与输出，不让 AI 猜 |
| 验收写成断言 | 「不产生文件」「序列必须是 T,T,T,F,T」「健康检查必须是 qwen」 |
| 一次只改一块 | 一个会话一个可验收目标，改完立刻 commit + 落快照 |
| 汇报必须复验 | 子代理说修好了，我用独立脚本再打一遍 |
| 回退留一行 | 新行为都做成开关，缺省等于旧行为 |
