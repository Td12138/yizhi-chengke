# 2026-11-15 · D0 · 选题合并论证与骨架落地

## 目标

在省赛截止（2026-11-18）前 3 天，确定作品选题、给出方案文档、落地可运行骨架。

## 关键 prompt（摘要）

1. 「传智杯 AI创新应用挑战赛 是作品赛。我现在要弄一个作品」
2. 提供 10 个方向清单，要求「把 AI 合并为一个，用现成的资料构建一个」
3. 「多 Agent 和 RAG 知识库呢？」—— 要求把多 Agent 与 RAG 都纳入，不能被砍掉
4. 「先出方案文档」

## AI 输出摘要

| 环节 | 结论 |
|---|---|
| 赛道核实 | AI 创新应用挑战赛（个人赛 / 技术应用赛）；提交物 = 公开仓库 + 细粒度 Git 历史 + AI 对话快照 + README + 5–8 min 视频 + ≤30 页 PDF；报名与作品提交截止 2026-11-18 |
| 合并方案 | 五个方向收敛为一条漏斗：拍照 → 版面块 → 卡片入库 → 一句话出题 → 质检 → 作答 → 讲解 |
| 架构 | 六个能力异构 Agent + 自研 asyncio 编排 + SSE 事件流看板 |
| 关键设计 | 命题 ↔ 质检回环（sympy 验算），用于证明多 Agent 的必要性 |
| 工程骨架 | FastAPI + SQLite + React/Vite + KaTeX，mock provider 全链路可跑 |

## 我的判断（采纳 / 否决）

| 决策 | 理由 |
|---|---|
| ✅ 一页漏斗，不堆十个方向 | 3 天窗口内堆功能必然烂尾，也容易被判成功能堆砌 |
| ✅ 保留多 Agent 与 RAG | 质检回环是唯一能让多 Agent 站得住的设计；RAG 是卡片库的自然延伸 |
| ✅ 只做一个可视化模板 | 三个模板不加分，只会挤掉录视频的时间 |
| ❌ 不引入 LangGraph | 3 天内调试成本高于收益；改为自研编排并保留可替换接口 |
| ❌ 不做公网部署 | 演示靠本地 + 预置数据 + 录屏兜底，降低现场风险 |
| ❌ 不复用私有工程整包 | 脱敏红线；只搬结构与经验，代码在干净仓库重写 |

## 落地结果

- 方案设计 v1.0：选题论证、3 天排期、Must/Cut 取舍、技术文档大纲、视频分镜
- 后端：六 Agent + 编排器 + Provider 抽象 + SQLite 模型
- 前端：Agent 看板、卡片列表、练习卷、KaTeX 渲染、函数图像参数滑块
- 验证：`ingest → generate → grade → ask` 全链路通过；质检回环实测驳回 1 题后重生成通过
