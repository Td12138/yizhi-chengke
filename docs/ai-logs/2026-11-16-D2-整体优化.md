## AI 输出摘要

- **三级验算**：`check_question_detailed` 返回级别 symbolic/structural/unchecked；无 verify 的题做结构检查（题干/答案/题型），不再冒充「已验算」；开关可回退旧行为。
- **等价判分**：LaTeX→纯文本 + 显式补隐式乘法（发现 sympy `evaluate=False` 与隐式乘法变换不兼容，会拼出非法 AST）+ safe_math 白名单 + simplify 差判等；顺带发现并修复旧误判「双方程右端值相同即判等」（x=2 vs y=2）。
- **留痕/归因/落库/混合检索**：card_revision 同事务记录真实变更；review prompt 增 student_method（mock 边界不变）；EventBus 落库 + 回放接口 + 前端重试兜底；RRF 融合检索，端点故障回退 legacy。
- **评测**：构造题库拦截率 100% / 误驳 0%；检索 top-3 legacy 80% → hybrid 95%（本地 BGE-M3 实测，唯一 miss 为英文跨语问句，如实记录）。
- **E2E**：Playwright 7 条主路径自管服务跑通；期间修正三处脚本问题（流式草稿题负 id 需等 done 校正、`<details>` 折叠态取不到文本、卡片流式入库需等数量到齐）。

## 我的判断

- **采纳全量范围**（用户决策）：两天窗口内 P2 也做，但混合检索缺省 legacy——嵌入端点不是评审环境标配，缺省行为必须零依赖。
- **结构性修复缺省启用**：工作区「功能变更做加法」要求缺省=旧行为；本次三级语义/等价判分/事件落库缺省开启、各带一行配置回退。理由：这是参赛作品的新版本而非在线服务灰度，「无 verify 标已验算」是表述缺陷，修复必须默认可见；回退成本仍是一行配置。
- **否决 sqlite-vec**：原生扩展增加评审环境装包风险，语料仅几十张卡，纯 Python 余弦足够；文档写明规模判断。
- **沿用既有否决**：视频录制（须本人）、真实模型联调（无 Key）、AGPL 换库、git 历史重写——不在本轮范围。
- **评测口径否决夸大**：拦截率只证明「验算环节拦得住坏题」，不证明真实模型出题错误率；检索数字限定 10 张卡规模。文档与 README 均按此写。
